# 势力系统

> **Status**: In Review
> **Author**: User + Claude (Sonnet 4.6)
> **Last Updated**: 2026-04-30 (post-review revision)
> **Implements Pillar**: 沙盒人生模拟 — 每局是独立的完整故事

## Overview

势力系统定义玩家在修仙世界的社会身份。每局开始时，玩家面对五家宗门与散修路线，做出第一个决定——这一决定决定了玩家的资源结构、社会关系网络、与世界事件的交互方式。

系统由三个子结构组成：**宗门名录**（五家宗门的规则与特质）、**考核系统**（各宗门的准入机制）、**faction_affinity**（玩家与各势力的数值化关系，驱动交易折扣、事件触发与 NPC 态度）。散修不属于任何宗门，以中立姿态在世界中行走。

归属不是终身的。玩家可在游戏中被驱逐、主动退宗、或中途入宗，所有变更操作通过统一的归属变更接口处理。

## Player Fantasy

修仙世界里，背靠宗门与独自漂泊是两种完全不同的活法。

**加入宗门**：门一旦进了，你就是这个圈子里的人。有师兄弟，有靠山，有规矩，也有归属。不同宗门的弟子走在江湖上，气质就是不一样——衍天宗弟子带着傲气，青云宗弟子带着正气，修罗门弟子带着煞气，草门弟子带着玄气，守一门弟子带着平气。

**散修**：没有庇护，没有负担。世界里所有的门对你打开，也对你关闭。靠自己，靠运气，靠在缝隙里找机会。不属于任何人，也没有任何人属于你。

**情绪目标**：玩家在选宗门时，感受的不是"选一个 buff 套装"，而是"选一种活法"。每个宗门的考核是那种活法的第一次预演。

## Detailed Design

### 宗门名录

五家宗门各有特质，代表五种不同的修仙路线。开局全部展示，玩家可对任意宗门发起考核。

#### 宗门一览

| 宗门 | 类型 | 入宗声望变化 | 年俸（灵石/年，按境界）| 坊市档次 | 任务风格 |
|------|------|------------|----------------------|---------|---------|
| 衍天宗 | 精英 | +60 | 练气30 / 筑基80 / 金丹200 / 元婴500 / 化神1200 | 稀缺资源最多，价格最低 | 同境界任务最难，奖励最高 |
| 修罗门 | 魔道 | -30 | 无 | 魔道专属稀缺物（正道坊市无法购得） | 高风险魔道任务，高回报 |
| 青云宗 | 正道 | +30 | 练气15 / 筑基40 / 金丹100 / 元婴250 / 化神600 | 正道稀缺资源，价格中等 | 同境界任务中高难度 |
| 草门 | 运气 | — | 无 | 商品随机（每次进入重新刷新） | 奇特任务，奖励幅度最宽（波动大） |
| 守一门 | 普通 | — | 练气5 / 筑基12 / 金丹30 / 元婴75 / 化神180 | 基础资源为主，价格偏高 | 同境界任务最简单，奖励最低 |

> 境界顺序：练气 → 筑基 → 金丹 → 元婴 → 化神（对应 realm 0–4）。
> 年俸每游戏年自动发放，入宗当年不发（次年起算）。
> 散修无年俸、无宗门坊市、无宗门任务池。

**修罗门坊市补偿（魔道专属道具，正道坊市不售）**

| 道具 | 价格 | 效果 | 使用条件 |
|------|------|------|---------|
| 血魄丹 | 100灵石 | 立即+80灵石，声望-8 | 声望≤-10 时可购 |
| 噬魂符 | 150灵石 | 当局一次困难任务失败结果升至"勉强" | 无限制 |
| 鬼域镜 | 300灵石 | 一次性：揭示下一个隐藏事件所有选项的真实奖励数值 | 声望≤-20 时可购 |

> 道具具体数值待 items.gd 实现时确认；以上为 Phase 1 设计基准。

**草门坊市规则（零年俸补偿）**

每次进入随机抽取5件商品，从全档次物品池中抽取（含衍天宗档次稀缺物）。价格比各物品对应标准价高20%，但无宗门准入限制。预期收益：期望中性，方差高——有概率以高价买到通常无法购得的稀缺物，也可能5件全是基础商品。这是零年俸的风险补偿，而非稳定收益。

### 考核系统

所有宗门考核均由两部分组成，两部分均需通过，任一失败即考核失败。

**通用结构**

| 部分 | 类型 | 通过条件 |
|------|------|---------|
| Part 1 | 文字情境题（5题） | 总分达到该宗门设定门槛（≥6） |
| Part 2 | 势力专属小游戴 | 达到该宗门设定通过线 |

**设计原则**：每家宗门的考核应是"该种活法的第一次预演"。题目情境、选项语气、小游戴机制，均需体现该宗门气质——考核本身就是入宗后生活的缩影。

**失败规则**：考核失败不扣声望、不给惩罚标记。该宗门本局不可再考（从选择列表中移除）。

**Part 2 — 守元功**

### faction_affinity 数据结构

`Player.faction_affinity: Dictionary` — 键为宗门名（含"散修"），值为整数，范围 **-100 ~ 100**。

```gdscript
# player.gd 中初始化
var faction_affinity: Dictionary = {
    "衍天宗": 0, "修罗门": 0, "青云宗": 0,
    "草门": 0, "守一门": 0, "散修": 0
}
```

**数值含义**

| 范围 | 含义 |
|------|------|
| 50 ~ 100 | 成员/友好（享受坊市折扣、任务加赠） |
| 0 ~ 49 | 中立 |
| -30 ~ -1 | 冷淡（NPC 态度变差） |
| -50 ~ -31 | 疏远（门内任务受限） |
| < -50 | 敌对（触发敌意事件，计划中） |

**变化时机**（当前已实现 / 计划中）

| 事件 | affinity 变化 | 状态 |
|------|-------------|------|
| 考核通过入宗 | 本宗 +50 | 已实现（隐式，通过 player.faction 判断） |
| 宗门任务完成 | 本宗 +5 | 待实现 |
| 宗门任务失败 | 本宗 -5 | 待实现 |
| 主动退宗 | 本宗 -30，散修 +10 | 待实现 |
| 被驱逐 | 本宗 -50 | 待实现 |
| 非成员宗门年度衰减 | 非本宗各宗 -2/年（趋向0） | 待实现 |

> **当前版本简化**：faction_affinity 尚未写入 player.gd。宗门关系仅通过 `player.faction`（字符串）和 `player.prestige`（全局）追踪。faction_affinity 字典留作下一迭代实现。

### 归属变更流程

**入宗**（当前已实现）
1. 玩家在宗门选择界面点击"拜入X门"
2. 触发对应考核流程
3. 考核通过 → `player.faction = 宗门名`，声望按 FACTIONS 表变化，`show_free()`

**失败**（当前已实现）
- 考核失败 → `_failed_factions.append(宗门名)`，该宗门从本局选择列表移除
- 失败不扣声望，不限制其余宗门考核

**五关全败**（当前已实现）
- `_failed_factions` 包含全部五家 → 选择界面仅剩"转身离开，做散修"

**散修**（当前已实现）
- 直接选择散修 → `player.faction = "散修"`，无声望变化

**退宗 / 驱逐**（待实现）
- 设计意图：玩家可主动退宗，代价为声望变化 = -(入宗声望奖励绝对值)，确保入-退净声望变化为零
  - 守一门/草门（入宗奖励=0）：退宗声望 -20（固定最低代价）
  - 青云宗（入宗+30）：退宗 -30（净变化 = 0）
  - 衍天宗（入宗+60）：退宗 -60（净变化 = 0）
  - 修罗门（入宗-30）：退宗 +20（部分补偿入宗损耗，净变化 = -10）
- 驱逐条件：faction_affinity 本宗 < -50（待定）
- 退宗后变为散修，已失败宗门不可重考（`_failed_factions` 保留）
- 中途入宗：暂不支持（开局一次性选择）

### Interactions with Other Systems

**player.gd**
- 读 `player.faction` 判断宗门归属
- 读/写 `player.prestige`：考核通过时按 FACTIONS 表修改
- `player.gold` 初始化：宗门选择界面固定 40 灵石开局
- **`player.join_year: int`（待新增字段）**：年俸"入宗当年不发"逻辑所需，入宗时赋值为 `player.age`，散修默认 -1。由逻辑 Agent 实施年俸功能时同步添加

**task.gd**（双向）
- task.gd 按 `player.faction` 过滤宗门任务来源（`source == "宗门任务"` 仅本宗可见）
- 声望 < -50 时 task_locked = true，宗门任务不可接
- faction-system → task-system：faction 决定任务池质量和难度风格（守一门最简/衍天宗最难）

**game.gd — market**
- 坊市档次由 `player.faction` 决定（当前未实现宗门专属坊市，统一用 MARKET_ITEMS）
- 声望 < -100 时进黑市（与 faction 无直接关联）

**game.gd — 年俸**（待实现）
- 闭关/行动消耗年份时触发年俸发放
- 发放额 = `FACTION_STIPEND[player.faction][player.realm]`（见宗门名录表）
- 入宗当年不发，次年起算

**minigame_logic.gd**（单向）
- faction-system 调用 MinigameLogic 节点，传入 pool（easy/medium/advanced）
- minigame_logic.gd 不感知 faction，只执行配置

**minigame_stopline.gd**（单向）
- faction-system 调用 MinigameStopline 节点，传入 preset 名
- minigame_stopline.gd 不感知 faction，只执行配置

## Formulas

### 年俸发放

```
年俸 = STIPEND_TABLE[faction][realm]

STIPEND_TABLE:
  守一门: [5, 12, 30, 75, 180]      # 练气~化神
  青云宗: [15, 40, 100, 250, 600]
  衍天宗: [30, 80, 200, 500, 1200]
  修罗门: [0, 0, 0, 0, 0]           # 无年俸
  草门:   [0, 0, 0, 0, 0]           # 无年俸
  散修:   [0, 0, 0, 0, 0]

发放条件: player.faction != "散修" AND 当年非入宗年
发放时机: 每次 player.pass_time() 调用时，按消耗年数累计发放
```

**变量定义**

| 变量 | 类型 | 范围 | 说明 |
|------|------|------|------|
| faction | String | 五宗+散修 | 当前归属 |
| realm | int | 0-4 | 练气=0，化神=4 |
| 年俸/年 | int | 0-1200 | 灵石 |

**示例计算**

青云宗弟子，筑基期（realm=1），闭关10年：
```
年俸收入 = 40 × 10 = 400 灵石
（入宗当年不计，此处假设已过一年）
```

### 考核得分

```
Part1 得分 = Σ selected_option["score"]
通过条件: Part1 得分 ≥ faction_threshold

守一门: threshold = 6，满分 = 10，最低 = -5
修罗门: threshold = 6，满分 = 10，最低 = -5
衍天宗: threshold = 6，满分 = 10，最低 = -5
青云宗: threshold = 6，满分 = 10，最低 = -5

草门：不适用此公式。草门走独立 EXAM_CAOMEN 路径（无积分制，见 考核系统 → 草门考核）。
```

**积分不透明原则**：Part 1 积分不向玩家展示。失败文本以宗门语气呈现，不包含数字反馈。

## Edge Cases

**E1 — 五宗考核全败**
玩家依次失败所有宗门考核 → `_failed_factions` 含五家 → 宗门选择界面仅显示"转身离开，做散修"按钮。游戏继续，无错误。

**E2 — 修罗门 Part2 死亡**
MinigameStopline 发出 `"death"` 信号 → `_show_xiuluo_exam_death()` 直接设置 `State.GAMEOVER`，跳过 `_handle_death_or_continue()`（不检查延寿丹）。死亡文本定制，与普通死亡文本不同。

**E3 — 修罗门 Part3 古堡选错门**
`_on_exam_gate_door()` 中 `door != rd["correct_door"]` → 调用 `_show_xiuluo_exam_death(rd["fail_death_text"])`。同 E2，直接 GAMEOVER，不走延寿丹检查。

**E4 — 草门：玩家30秒内操作了其他按钮**
点击 Step 1-4 任一按钮 → `_on_caomen_fake_btn()` 立即执行，设置 `State.EXAM_RESULT`。此后 `_process()` 中 `current_state != State.EXAM_CAOMEN`，30秒计时停止，不触发二次通过。

**E5 — 草门：玩家点击"随缘"后30秒计时仍在运行**
`_on_caomen_random()` → `_show_exam_result(true)` → `current_state = State.EXAM_RESULT`，`_process()` 中 EXAM_CAOMEN 分支不再执行，无冲突。

**E6 — MinigameLogic "advanced" 题库为空或不存在**
MinigameLogic 内部处理：若指定 pool 为空，应 fallback 至 easy 题库（MinigameLogic 实现保证，需验证）。若 MinigameLogic 直接报错，考核卡死。**风险：需在 minigame_logic.gd 中验证 advanced pool 非空。**

**E7 — 衍天宗 Part1 两题均选最低分（0+0=0）**
得分0 < 阈值3 → 考核失败，走 Part1 失败文本，衍天宗加入 `_failed_factions`。正常。

**E8 — 青云宗 Part1 三题均选-1分（总分-3）**
得分-3 < 阈值3 → 考核失败。负分不影响任何其他系统（prestige 不变，声望只在通过时修改）。

**E9 — 玩家在 EXAM_MINIGAME 状态下点击返回**
当前实现无返回按钮，守一门波动界面只有"稳住"按钮。如需添加返回，须将该宗门加入 `_failed_factions`（视为主动放弃 = 失败）。**当前版本：无返回按钮，无此 edge case。**

**E10 — player.join_year 字段初始化**
player.gd 需新增 `join_year: int` 字段（默认值 -1 表示未入宗）。入宗时由 game.gd 设置为当前游戏年份（`player.age` 整数部分）。年俸发放逻辑：`if player.age - player.join_year < 1: skip`。散修 join_year 保持 -1，年俸发放条件 `player.faction != "散修"` 覆盖此情况。逻辑 Agent 实施年俸功能时须同步新增此字段。

**E11 — STIPEND_TABLE realm 越界保护**
`pass_time()` 年俸发放前执行 `realm = clampi(player.realm, 0, 4)`。若 player.realm 因存档迁移或 bug 超出 0–4 范围，回退至最高合法境界（4）不崩溃。逻辑 Agent 实施时在 game.gd 年俸发放处加 clamp 保护。

## Open Questions

1. **年俸实现时机**：`player.pass_time(years)` 内累积发放，还是每个"年份结算"事件独立触发？推荐在 `pass_time()` 内按年数乘以年俸单价，一次性结算。
2. **faction_affinity 何时实现**：当前版本仅 `player.faction` 字符串追踪。affinity 字典留待 NPC 系统接入后实现，避免无消费者的过早设计。
3. **中途入宗**：当前设计为开局一次性选择。是否允许散修后期通过特殊事件加入某宗门？暂不支持，留作扩展点。
4. **衍天宗 advanced 题库**：需确认 `minigame_logic.gd` 中 `"advanced"` pool 存在且非空，否则 Part3 无法正常启动（见 Edge Case E6）。

## Known Gaps for Phase 2

以下为 Phase 1 范围内的已知设计差距，不阻塞当前实现，记录为 Phase 2 目标：

1. **宗门差异化为经济层级**：Phase 1 宗门差异 = 年俸 + 声望 + 市场 + 任务池。Player Fantasy "选一种活法"在 Phase 1 仅部分兑现（入宗体验差异化，后期无行为约束）。Phase 2 在 story_one.gd / story_more.gd 加入 `faction_filter` 字段，实现宗门事件分流。

2. **散修 Phase 1 定位**：散修无年俸、无宗门任务池。Phase 1 隐性优势：声望从零积累且无宗门义务，hidden_chance 积累速度不受负声望拖累。Phase 2 计划添加散修专属事件分支和灰色机缘池。

3. **三宗考核骨架雷同**：守一门/衍天宗/青云宗 考核结构相同（Q&A → Stopline → Logic），仅参数差异。Phase 2 可探索各宗门独有考核机制。

4. **草门考核重玩性**：二周目 = 30 秒等待，体验单一。Phase 2 可探索随机化元素。

5. **高境界年俸结构差距**：衍天宗 vs 守一门元婴期 200 年产生约 85,000 灵石结构差。需 economy.md Phase 2 设计 gold sinks（突破消耗、稀缺物品采购等）吸收积累。

6. **faction_affinity 系统**：`player.faction_affinity` 字典已落地（入宗 = 50），但下游消费方仅 origin-mechanism.md / faction-system.md 自身。Roguelike 重定位后已无 NPC 态度系统需要消费此字段，保留以备未来宗门间事件链使用。
